### WS-3 — Desktop key-derivation fix + doc truth-up
- **Status:** ✅ done
- **Finding IDs:** F-05, F-06, F-07 (+ unaudited bonus: fabricated `tauri-plugin-stronghold` claim)
- **Locked decision applied:** legacy (pre-2026-07-29) encrypted key files are **discarded, not
  migrated** — `getApiKey` detects the missing-`salt`-field legacy format, deletes the stale file,
  and dispatches a one-time `statusActions.addNotification` (type `info`, "API Key Reset
  Required") via `appStoreRef`, rather than a silent `return null` indistinguishable from "no key
  ever set".
- **Code fix:** `services/fs/fsCore.ts` `deriveFileSystemCryptoKey` — single unsalted
  `crypto.subtle.digest('SHA-256', ...)` → PBKDF2 (600 000 iterations, SHA-256) + random 32-byte
  salt persisted alongside the ciphertext, `extractable: false` — mirrors
  `services/storage/storageEncryptionService.ts#deriveKey` exactly (same iteration constant).
- **Two real TS strictness bugs caught and fixed during verification** (not in the original
  audit — surfaced by `pnpm run typecheck`, the exact CI command):
  1. `base64ToBytes`'s bare `Uint8Array` return-type annotation widened to
     `Uint8Array<ArrayBufferLike>` (includes `SharedArrayBuffer`), rejected by `crypto.subtle` as
     a `BufferSource`. Fixed with an explicit `Uint8Array<ArrayBuffer>` annotation — same pattern
     already established in `services/libraryBackupService.ts#copyToFixedBuffer`.
  2. `getApiKey`'s `let apis: TauriApis | undefined` couldn't narrow across the `retryFs(() =>
     apis.readTextFile(...))` closure boundary. Fixed by using a properly-scoped `const apis`
     inside the `try` block and separate outer `let apisForCleanup`/`keyFileForCleanup` refs for
     the catch-block cleanup path.
- **Regression tests:**
  - `tests/unit/services/fs/fsCore.test.ts` — two encryptions of the same secret+plaintext now
    produce different salt/iv/ciphertext; a payload with no `salt` field rejects with a
    legacy-specific error message.
  - `tests/unit/services/fs/fsStores.test.ts` — new test asserts the full discard path through
    `FsSettingsStore.getApiKey`: returns `null`, removes the stale file from the fake FS, and the
    mocked `appStoreRef.current.dispatch` was called with the expected notification shape.
  - `pnpm exec vitest run tests/unit/services/fs/fsCore.test.ts tests/unit/services/fs/fsStores.test.ts` → **40/40 passed**.
